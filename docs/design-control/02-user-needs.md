# 02 User needs

**What it's for:** write down what users need, in their own words, before anyone thinks about solutions.

## Questions it answers

- Who uses the device, and who is it used on?
- Where is it used: light, noise, stress, weather?
- What problem does it solve for them?
- What would "this worked" look like to them?

## Step 1: write the intended use statement

One paragraph that everything else must fit inside. Example:

> The device helps emergency responders and minimally trained volunteers decide which patient to see first in a disaster setting. It measures SpO2, blood pressure and heart rhythm and suggests a High, Medium or Low priority. It supports clinical judgement and does not replace it. Patient population: [team to decide].

## Common mistakes

- **Writing solutions.** "Needs an OLED screen" is a design choice. The need is "I can read the result in bright sun."
- **Several needs in one row.** Split them so each can be traced.
- **Treating judges as users.** Their scoring criteria are a useful source, but write each need from the responder's or patient's point of view.
